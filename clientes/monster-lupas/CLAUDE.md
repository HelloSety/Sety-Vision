## Migração para Shopify (2026-08-04)

Loja real: `hello-world-uaavn-tjngdsf5.myshopify.com` (nome de dev store gerado automaticamente — Seven confirmou que é loja paga real, apesar do handle). Projeto local em `monster-lupas-shopify/` (clone do tema Dawn 15.5.0 da Shopify, customizado).

**Tema:** base Dawn com identidade Monster Lupas aplicada via `assets/monster-lupas.css` (paleta preto/branco/cinza, Google Fonts Sora+Montserrat injetadas manualmente no `layout/theme.liquid` já que não estão na biblioteca nativa do Shopify — CSS vars `--font-heading-family`/`--font-body-family` sobrescritas). Sections customizadas criadas: `ml-marquee` (faixa de benefícios), `ml-banner` (banners hero usando assets do tema via `asset_url`, não o `image_picker` nativo — ver nota abaixo), `ml-sticker-categories` (compre por modelo com tabs de categoria filtrando por tag via JS), `ml-carousel` (carrossel de coleção reutilizável, usado em Novidades/Destaques/Colecionador/Performance), `ml-instagram-bar`. Produto customizado via blocks `custom_liquid` no `main-product` nativo (badges Compre1Leve2, Pix 5% off calculado em Liquid, parcelamento, ícones de pagamento, trust list) — sem fork do `main-product.liquid`. Galeria do produto usa `gallery_layout: "thumbnail"` + `media_position: "left"` (nativo do Dawn, sem código customizado).

**Armadilha descoberta:** `image_picker` settings (usado em `image-banner` nativo, no `settings.logo` do header, no `settings.favicon`) só aceita imagens já enviadas à Shop Image Library (`shopify://shop_images/...`) — **não** aceita referenciar um asset do tema (`assets/arquivo.webp`) diretamente. Por isso os banners viraram uma section customizada (`ml-banner.liquid`) que usa `asset_url` em vez de `image_picker`. Logo do header e favicon settings não têm esse contorno (são componentes nativos do Dawn) — ficam como upload manual de 1 clique no Theme Editor, documentado nas instruções de entrega.

**Catálogo:** script `scripts/generate-shopify-csv.js` lê `site/js/catalog.js` (fonte única de verdade do catálogo, compartilhada com o site estático) via `vm.runInNewContext` e gera `monster-lupas-shopify/produtos-monster-lupas.csv` no formato de import padrão Shopify — 31 produtos, 248 variantes de cor (option "Cor"), preço R$179,90/compare-at R$297,90, tags `categoria-<slug>` e `colecao-<slug>` (mapeiam pras tabs de categoria e pras 3 collections automáticas que precisam ser criadas manualmente no Admin: `colecao-novidades`, `colecao-colecionador`, `colecao-performance`). Imagens referenciadas por URL absoluta — as 4 hotlink direto de monsterlupas.com.br (mesmas que o catalog.js já usava) e as ~200 locais servidas do site em produção (`https://site-pi-six-62.vercel.app/assets/produtos/...`), que o Shopify baixa e re-hospeda no próprio CDN durante o import (não cria dependência permanente do Vercel).

**Deploy:** `shopify theme push --unpublished` criou o tema como rascunho (id `191738642754`) na loja. Publicado ao vivo no mesmo dia via `shopify theme publish --force` (Seven pediu explicitamente "publicar o tema" — `--force` necessário pois o prompt de confirmação do CLI é interativo e não funciona neste ambiente). Loja ao vivo: https://hello-world-uaavn-tjngdsf5.myshopify.com — ainda sem produtos importados nem coleções criadas até o Seven rodar os 3 passos manuais documentados. Bloqueio encontrado: conta logada no CLI não tinha acesso à dev store ("you don't have access to this dev store") até o Seven se adicionar como staff — depois de `shopify auth logout` + novo device-code login, funcionou. Erro de validação no primeiro push: bloco `text` do footer (richtext) não aceita atributo `class` em `<a>` — Shopify sanitiza HTML de campos richtext e só permite `href`/`target`/`rel`; resolvido removendo a classe e usando `<strong>` puro.

**Entregáveis alternativos** (caso o acesso via CLI falhe de novo): `.zip` do tema (pastas assets/config/layout/locales/sections/snippets/templates, sem `.git`) via `Compress-Archive` do PowerShell + o CSV, ambos deixados em `C:\Users\seven\Downloads\` pro Seven subir manualmente via Admin → Loja Online → Temas → Adicionar tema → Upload zip, e Admin → Produtos → Importar.

## Automação completa via Admin API (2026-08-04, rodada final)

Depois do primeiro push, Seven pediu pra automatizar tudo que antes ficou marcado como "1 clique manual" (logo, collections, produtos). Autenticado via `shopify store auth --store ... --scopes write_products,read_products,write_files,read_files` (1ª tentativa deu timeout — a janela de OAuth não abriu/foi percebida a tempo; funcionou na 2ª tentativa). A partir daí, tudo foi feito com `shopify store execute --allow-mutations` (GraphQL Admin API direto), sem precisar de token de app custom.

- **Logo do header:** staged upload real (`stagedUploadsCreate` → POST multipart via `curl -F` pro Google Cloud Storage → `fileCreate` com `originalSource` sendo o `resourceUrl` do staged target → poll até `fileStatus: READY`) → referenciada em `config/settings_data.json` como `"logo": "shopify://shop_images/monster-lupas-logo.png"`. Esse fluxo resolve a limitação de `image_picker` documentada acima — não precisa mais de upload manual.
- **7 collections automáticas** criadas via `collectionCreate` (ruleSet por tag): `novidades`, `edicao-colecionador`, `linha-performance` (temáticas) + `linha-x-metal`, `linha-esportiva`, `linha-classica`, `linha-streetwear` (categorias). `templates/index.json` atualizado pra referenciar os handles reais nos carrosséis.
- **Tabs de categoria viraram links reais:** `ml-sticker-categories.liquid` reescrita — os blocks `category_tab` agora usam um `collection` picker (não mais campo de texto "tag") e renderizam `<a href="{{ collection.url }}">` em vez de `<button data-ml-tab>` com filtro JS. Clicar leva direto pra página da coleção (bom pra SEO e pra o cliente entender a navegação). O filtro client-side foi removido de `assets/ml-theme.js` (código morto).
- **Bug do SVG da seta "próximo" corrigido:** o path `d="m9 18 6-6 6 6"` (com espaço) desenhava um chevron pra CIMA em vez de um ">" — o parser de path SVG trata espaço/vírgula/sinal-de-menos como delimitadores equivalentes, então "6-6 6 6" tokeniza igual a "6,-6,6,6" (dois segmentos na mesma direção = "^"), não igual a "6,-6,-6,-6" (chevron direita real). Corrigido pra `"m9 18 6-6-6-6"` em `ml-carousel.liquid` e `ml-sticker-categories.liquid`. Posição das setas também mudou de `right:-6px`/`left:-6px` (dependia do wrapper ter exatamente a largura do conteúdo) pra `right:10px`/`left:10px` (sempre dentro da faixa visível, mais robusto).
- **Seção "Sobre" com logo real:** `image-with-text` nativo trocado por uma section customizada `ml-about.liquid` que usa `asset_url` (mesmo motivo do `ml-banner` — `image_picker` não aceita asset do tema).
- **Produtos importados via API (não CSV):** `scripts/import-products-api.js` — para cada produto: `productSet` (cria produto + opções + variantes, sem imagem) → `productCreateMedia` em lote (todas as imagens do produto de uma vez, casadas por `alt` text único `"{Nome} — {Cor}"`) → `productVariantAppendMedia` (associa cada mídia à variante certa). `productSet` com `file` direto na variant (`ProductSetVariantInput.file`) **não funciona** — dá erro "Origem do arquivo ausente"; a mídia precisa ser criada separada e associada depois. SEO título/descrição gerados por produto (`"{Nome} — {Categoria} | Monster Lupas"` + tagline+UV400+frete grátis, truncado a 160 char).
- **Achado crítico — loja já tinha 17 produtos de uma importação anterior (22/07, antes desta sessão):** duplicados (handles tipo `oculos-dartboard` E `oculos-dartboard-1`), nomenclatura diferente (`"Óculos Dartboard"` em vez de `"Dartboard"`) e provavelmente preço errado. ## Bug: produtos somem do site (2026-08-04)

Sintoma: home ao vivo mostra headings dos carrosséis ("Novidades", "Nossa Coleção" etc.) mas nenhum produto — `/collections/<handle>` retorna 404 ou 0 produtos.

Causa: produtos/collections criados via Admin API (`productSet`, `collectionCreate`) **não são publicados automaticamente em nenhum canal de vendas** — diferente de criar pelo Admin UI, que publica em todos os canais por padrão. Confirma via GraphQL: `resourcePublicationsV2 { edges }` vazio no produto/collection.

Correção: `publishablePublish(id, input: [{publicationId: "<id do canal Loja virtual>"}])` para cada produto/collection. ID do canal via `publications(first:5)` (nome "Loja virtual"). Requer scopes `read_publications,write_publications,read_product_listings` além dos já usados (`write_products,read_products,write_files,read_files`) — reautenticar com `shopify store auth --scopes ...` se o token atual não tiver.

**Checklist obrigatório após qualquer import de produto/collection via API nesta loja:** confirmar publicação no canal Loja Virtual antes de considerar a entrega concluída.
